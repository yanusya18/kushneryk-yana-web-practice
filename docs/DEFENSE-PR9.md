# Підготовка до захисту ПР 9

## Контрольні питання
**1. Що вимірюють Core Web Vitals (LCP, CLS, INP) і які «добрі» значення?**
- **LCP** (Largest Contentful Paint) — за скільки відображається найбільший елемент першого екрана (у нас — hero-зображення). Добре: ≤ 2,5 с.
- **CLS** (Cumulative Layout Shift) — наскільки «стрибає» макет під час завантаження. Добре: ≤ 0,1. Знижуємо явними `width`/`height` на зображеннях і резервуванням місця під повідомлення форм.
- **INP** (Interaction to Next Paint) — затримка реакції сторінки на дії користувача (клік, введення). Добре: ≤ 200 мс.

**2. Які чотири принципи WCAG (POUR)?**
**P**erceivable (сприйнятний: alt, контраст), **O**perable (керований: клавіатура, видимий фокус, skip-link), **U**nderstandable (зрозумілий: підписи, повідомлення про помилки), **R**obust (надійний: семантичний HTML, ARIA, сумісність з екранними читачами).

**3. Чим ручне тестування відрізняється від модульного?**
Ручне — людина проходить сценарії в браузері за чек-листом (бачить дизайн, UX, адаптивність), повільне, але знаходить «живі» проблеми. Модульне (unit) — код перевіряє окремі функції/компоненти автоматично й швидко (`npm test`), повторюється після кожної зміни й ловить регресії. Вони доповнюють одне одного.

**4. Для чого потрібні sitemap.xml і robots.txt?**
`robots.txt` каже пошуковим ботам, що можна обходити, і вказує адресу sitemap. `sitemap.xml` — список адрес сайту для індексації (у нас генерується з даних місць, тому сторінки `/items/N` потрапляють туди автоматично).

## Ключові фрагменти для пояснення
- **`React.lazy` + `Suspense`** (`App.jsx`, `Layout.jsx`): `lazy(() => import(...))` завантажує код сторінки лише при переході; `Suspense` показує запасний вміст, поки файл вантажиться.
- **`<picture>` з AVIF/WebP/JPG** (`Picture.jsx`): браузер перебирає `<source>` зверху вниз і бере перший формат, який підтримує; `<img>` — запасний варіант і носій `alt`, `width`, `height`.
- **`applySeo`** (`utils/seo.js`): оновлює `<head>` при зміні маршруту; шукає наявний `<meta>` і змінює його, щоб не було дублікатів.
- **JSON-LD** (`buildWorkspaceJsonLd`): структуровані дані Schema.org, за якими пошуковик розуміє, що це товар/послуга з ціною в гривнях.
- **Skip-link + керування фокусом** (`Layout.jsx`): у SPA сторінка не перезавантажується, тому фокус і оголошення назви сторінки робимо вручну.
- **Тести**: `validators.test.js` (регулярні вирази email/+380), `booking.test.js` (перетин проміжків 10–13 і 13–15 — не конфлікт), `FormField.test.jsx` (label ↔ input, `aria-describedby`), `Header.test.jsx` (`aria-expanded`).

## Що показати викладачу
1. Звіти Lighthouse «до/після» й таблицю в `docs/AUDIT.md`.
2. `npm test` — усі тести зелені.
3. Прохід сайту клавіатурою: Tab → skip-link → меню → форма → модалка → Esc.
4. Різні `title`/`description` у `<head>` на двох сторінках, JSON-LD на `/items/1`.
5. axe DevTools — 0 критичних помилок.
6. Готовність пояснити, чому зображення в AVIF, і чому ставимо `width`/`height`.
