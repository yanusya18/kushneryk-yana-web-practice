# JavaScript у проєкті (ПР 6)

## Як запускати
ES-модулі та `fetch` **не працюють з `file://`** (браузер блокує). Потрібен локальний сервер:
- VS Code → розширення **Live Server** → правий клік на `client/static/index.html` → *Open with Live Server*;
- або в терміналі: `cd client && python -m http.server 8000`, далі `http://localhost:8000/static/index.html`.

## Архітектура
```
client/assets/js/
├── main.js       # спільний вхід: клас .js, меню, тема, картки на головній
├── ui.js         # бургер, тема, модалка, делегування
├── form.js       # універсальна валідація форм
├── api.js        # дані: fetch JSON, localStorage, демо-режими
├── booking.js    # чиста логіка бронювання (перетини, вартість)
├── utils.js      # debounce, escapeHtml, дати, підписи
├── catalog.js    # каталог: фільтри, сортування, стани
├── workspace.js  # сторінка місця + бронювання
└── contacts.js   # контактна форма
```
Правило: **DOM — лише в `ui.js` і файлах сторінок; дані — лише в `api.js`**. У ПР 8 змінюється тільки `api.js` (fetch до Express).

## Відповідність вимогам ПР 6
| Вимога | Де |
|---|---|
| Модулі `ui.js`, `form.js`, `api.js` | `assets/js/` |
| 3 інтерактивні елементи | бургер-меню, перемикач теми (localStorage), модальне вікно (Esc + клік поза ним) |

| Динамічні картки | `catalog.js` → `renderCard` |
| Стани loading / error / empty | `catalog.js` (`showLoading`, `showError`, `showEmpty`) |
| Пошук, фільтр, сортування, debounce 300 мс | `catalog.js` + `utils.js → debounce` |
| Бронювання на дату й час | `workspace.js`, `booking.js`, `api.js → createBooking` |

## Демонстрація станів
Додайте параметр до адреси каталогу:
- `catalog.html?demo=loading` — індикатор завантаження (3 с);
- `catalog.html?demo=error` — помилка з кнопкою «Спробувати ще раз»;
- `catalog.html?demo=empty` — немає даних.
Фільтри теж працюють з адреси: `catalog.html?q=вікна&type=open-space&max_price=100`.

## Як працює бронювання
1. Дата → завантажуються вже зайняті години цього місця (`bookings.json` + ваші бронювання з localStorage).
2. Час початку/завершення — лише повні години 08:00–22:00; кінець пізніше за початок; на сьогодні час має бути майбутнім.
3. Перевірка перетину: `start1 < end2 && start2 < end1` (`booking.js → overlaps`). 10–13 і 13–15 **не** перетинаються.
4. Вартість = ціна за годину × кількість годин; показується в блоці підказки.
5. Кнопка «Забронювати» активна лише коли все коректно. Після submit `createBooking` ще раз перевіряє доступність і зберігає запис у localStorage; з'являється модальне вікно.
6. Кнопка «Очистити мої бронювання» видаляє лише записи користувача (для повторного тестування).

> Це клієнтська частина. Захист від подвійного бронювання на сервері й спільна база бронювань — у ПР 8.
