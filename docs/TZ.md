## 1. Призначення проєкту

### 1.1. Мета сайту
Дати відвідувачам коворкінгу зручний онлайн-спосіб: ознайомитись із простором,
побачити доступні робочі місця, їхні характеристики та ціни й **забронювати
місце на конкретну дату та час** без дзвінків адміністратору. Для коворкінгу —
зменшити ручну роботу з бронюваннями та показати простір у вигляді сучасного сайту.

### 1.2. Цільова аудиторія

| Група | Опис | Що їй потрібно |
|---|---|---|
| Фрилансери (дизайнери, розробники, копірайтери) | 20–40 років, працюють віддалено | Тихе місце на день/годину, швидкий інтернет, зрозуміла ціна |
| Студенти | 18–25 років | Недороге місце для курсової/диплома, погодинна оплата |
| Невеликі команди / стартапи | 2–8 осіб | Кілька місць поруч, переговорна, гнучкість |
| Працівники на віддаленні | 25–45 років | Резервна локація, коли вдома немає умов для роботи |

### 1.3. Ключові сценарії використання

1. **Забронювати місце.** Користувач відкриває каталог → обирає місце → дивиться
   деталі → обирає дату та час → вводить ім'я й контакти → отримує підтвердження.
2. **Порівняти варіанти та ціни.** Користувач переглядає каталог, фільтрує за типом
   місця (open space, фіксоване, кабінет, переговорна) та ціною, відкриває
   сторінки деталей.
3. **Зв'язатися з коворкінгом.** Користувач заповнює контактну форму (питання про
   оренду, екскурсію, корпоративні умови) і отримує повідомлення про успішне надсилання.

## 2. Аналіз конкурентів

> **Важливо.** Аналіз зроблено за відкритими публічними джерелами (сайт Spaces,
> добірки The Page про коворкінги Києва). Перед здачею **відкрийте кожен сайт
> і перевірте/доповніть** пункти, позначені «перевірити» — викладач може
> попросити показати, на що ви спиралися.

### 2.1. Spaces (spacesworks.com, локація Київ — Misto)
Міжнародна мережа коворкінгів.
- **Сильні сторони:**
  1. Миттєве бронювання через сайт або застосунок без дзвінків і контрактів.
  2. Чітка структура пропозицій: коворкінг-абонемент, виділене місце, денний офіс,
     переговорні; є додаткові послуги під час бронювання.
- **Слабкі сторони:**
  1. Великий корпоративний сайт з багатьма розділами та міжнародними локаціями —
     для користувача, який шукає одне місце, шлях до бронювання довгий (перевірити).
  2. Орієнтація на корпоративний/преміальний сегмент; для студентів та
     фрилансерів з обмеженим бюджетом ціна може бути завищеною (перевірити).

### 2.2. WORKIT SPACE (Київ, Нивки)
Локальний коворкінг з open space, офісами для команд і переговорною.
- **Сильні сторони:**
  1. Гнучка оплата: оренда місця від однієї години; окремі тарифи на незакріплене
     та фіксоване місце (за даними The Page).
  2. Зрозумілий склад пропозиції: open space, офіси для команд, переговорна.
- **Слабкі сторони:**
  1. Не знайдено підтвердження повноцінного онлайн-бронювання з вибором конкретного
     місця на дату й час (перевірити на сайті).
  2. Ціни та наявність місць, імовірно, потрібно уточнювати окремо
     (перевірити); немає візуального вибору місця.

### 2.3. Anthill Space (Київ)
Коворкінг, де можна орендувати робоче місце, офіс чи конференц-зал.
- **Сильні сторони:**
  1. Кілька форматів оренди: робоче місце, офіс, конференц-зал.
  2. Прозора стартова ціна на місяць (за даними The Page).
- **Слабкі сторони:**
  1. Основний акцент — оренда на місяць; погодинне/поденне бронювання
     на сайті потрібно перевірити.
  2. Інформація про конкретні робочі місця (фото, обладнання, розташування)
     імовірно подана узагальнено (перевірити).

### 2.4. Висновок для нашого проєкту
Конкуренти надають або загальну інформацію, або складний шлях до бронювання.
Наша перевага: **короткий шлях «каталог → місце → дата й час → підтвердження»**,
чіткі характеристики кожного місця, погодинні тарифи, мінімалістичний дизайн.

## 3. Структура сайту (карта сайту)

```
Головна (/)
├── Каталог робочих місць (/catalog)
│   └── Деталі місця + бронювання (/items/:id)
├── Послуги та ціни (/pricing)        — може бути секцією головної
├── Про коворкінг (/about)            — може бути секцією головної
├── Контакти + форма (/contacts)
└── Сторінка 404
```

**Мінімум 4 сторінки (вимога практики):** Головна · Каталог · Деталі місця
(з формою бронювання) · Контакти (форма зв'язку).

| Сторінка | Призначення | Ключові блоки |
|---|---|---|
| Головна | Перше враження, пояснення пропозиції | Hero + CTA «Забронювати», переваги, популярні місця, ціни, відгуки, футер |
| Каталог | Список сутностей «робоче місце» | Фільтри, пошук, сітка карток, стани loading/empty |
| Деталі місця | Інформація про одне місце + бронювання | Галерея, характеристики, ціна/год, форма: дата, час, ім'я, контакти |
| Контакти | Зв'язок із коворкінгом | Форма, адреса, графік, мапа |

## 7. Структура даних

### 7.1. Workspace — робоче місце (основна сутність, CRUD)

| Поле | Тип | Обов'язкове | Опис |
|---|---|---|---|
| id | number | так | унікальний ідентифікатор |
| name | string | так | назва, напр. «Місце A1 — біля вікна» |
| type | string | так | `open-space` / `fixed-desk` / `private-office` / `meeting-room` |
| description | string | так | опис місця |
| pricePerHour | number | так | ціна за годину, грн |
| capacity | number | так | кількість осіб (1 для столу) |
| amenities | string[] | ні | обладнання: `monitor`, `socket`, `wifi`, `lamp` ... |
| image | string | так | шлях до зображення |
| imageAlt | string | так | текст `alt` |
| isActive | boolean | так | чи доступне місце для бронювання |

### 7.2. Booking — бронювання (обов'язкова функція)

| Поле | Тип | Обов'язкове | Опис |
|---|---|---|---|
| id | number | так | ідентифікатор |
| workspaceId | number | так | зв'язок із Workspace |
| date | string (YYYY-MM-DD) | так | дата |
| startTime | string (HH:MM) | так | початок |
| endTime | string (HH:MM) | так | кінець (> startTime) |
| customerName | string | так | ім'я клієнта |
| customerEmail | string | так | email |
| customerPhone | string | так | телефон `+380XXXXXXXXX` |
| totalPrice | number | так | розрахована вартість |
| status | string | так | `confirmed` / `cancelled` |
| createdAt | string (ISO) | так | час створення |

**Правило доступності:** два бронювання одного `workspaceId` на одну `date`
конфліктують, якщо `start1 < end2` **і** `start2 < end1`.

### 7.3. ContactMessage — повідомлення з форми

| Поле | Тип | Обов'язкове |
|---|---|---|
| id | number | так |
| name | string | так |
| email | string | так |
| phone | string | ні |
| message | string (≥ 10 символів) | так |
| createdAt | string (ISO) | так |

### 7.4. Зв'язки
`Workspace 1 ── N Booking` (одне місце має багато бронювань). `ContactMessage` — окрема сутність.

## 8. Взаємодія клієнта і сервера

```
Браузер (React-клієнт) ──HTTP/JSON──▶ Express API ──▶ JSON-файли
        ◀──── відповідь 200/201/400/404/409/500 ──────
```

Клієнт надсилає запити `GET /api/items`, `POST /api/bookings`, `POST /api/contact`;
сервер валідує дані, перевіряє доступність, записує в JSON і повертає статус-код.
(Реалізація — ПР 6–8; до цього використовується локальний `data.json`.)

## 9. Візуальний напрям

Сучасний мінімалізм, технологічна та комфортна атмосфера, природне світло,
якісні фото інтер'єру, продумана типографіка, обмежена палітра без надлишкових
градієнтів. Єдина дизайн-система для всіх сторінок (розробляється в ПР 3).
