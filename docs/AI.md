# Використання AI-асистента (ПР 7)

Методичка вимагає: підключити AI-асистент кодингу (GitHub Copilot, Cursor або Claude Code),
виконати з ним **3 задачі** (генерація компонента, рефакторинг, пояснення чужого коду) і заповнити
таблицю: **промпт → що згенерував асистент → що виправлено вручну і чому**.

> ⚠️ Таблиці нижче порожні **навмисно**. Їх треба заповнити за результатами **вашої** роботи
> з асистентом: що ви справді запитали, що він видав і що ви виправили. Придумані записи
> на захисті одразу видно, бо викладач попросить показати історію чату або diff.

**Чесно зазначте у звіті:** стартову структуру React-застосунку з цього архіву (компоненти, хуки,

пояснити будь-який файл: для цього є `docs/COMPONENT-TREE.md`.

## 2. Як підключити асистента (коротко)

Конкретні кроки змінюються, тому дивіться офіційні інструкції:

- **GitHub Copilot** — розширення «GitHub Copilot» (і «Copilot Chat») у VS Code, вхід через акаунт GitHub.
  Є безкоштовний тариф; для студентів зазвичай діє освітня програма GitHub Education.
- **Cursor** — окремий редактор (cursor.com), відкрийте в ньому папку проєкту.
- **Claude Code** — інструмент у терміналі; встановлення й вхід — за документацією https://docs.claude.com.

Як перевірити, що все працює: відкрийте `client/`, у чаті асистента попросіть «поясни, що робить файл `src/App.jsx`» —
він має відповісти за вашим кодом, а не загально.

## 3. Три обов'язкові задачі

Нижче — **пропозиції** промптів. Можна взяти свої. Копіюйте промпт у асистента, а результат
оцінюйте самі за чек-листом у розділі 5.

### Задача 1. Генерація компонента
Промпт (приклад):
> У проєкті React (Vite) у `client/src/components` створи компонент `CardSkeleton` — сіру «заглушку»
> картки робочого місця на час завантаження (замість спінера). Використай лише CSS-змінні з
> `client/assets/css/tokens.css`, без нових бібліотек. Додай `aria-hidden="true"`. Підключи його в `CardList`
> у стані `loading` (6 штук). Стилі додай у `src/app.css`.

### Задача 2. Рефакторинг
Промпт (приклад):
> У `src/components/BookingForm.jsx` формування підказки про зайняті години й вартість (масив `info`)
> перероби на чисту функцію `buildBookingInfo({ date, busy, loading, start, end, pricePerHour })` у новому файлі
> `src/utils/bookingInfo.js`. Поведінка й тексти мають залишитись такими самими. Не чіпай інші файли.

### Задача 3. Пояснення чужого коду
Промпт (приклад):
> Поясни рядок за рядком, як працює хук `src/hooks/useFetch.js`: навіщо змінна `ignore`, що таке
> `attempt`, чому `fetcher` має бути стабільним і що станеться, якщо передати новий `fetcher` на кожному рендері.
> Наприкінці наведи приклад, коли без `ignore` з'явилась би помилка.

## 5. На які помилки AI звертати увагу (чек-лист для вашого аналізу)

Перевіряйте код асистента саме за цим списком — це типові слабкі місця, і про них питатимуть:

- [ ] **Залежності `useEffect`**: чи не пропущено змінну в масиві залежностей; чи немає нескінченного циклу.
- [ ] **`key` у списках**: стабільний `id`, а не індекс масиву.
- [ ] **Мутація стану**: `push`/`sort` на самому масиві зі стану замість копії.
- [ ] **Вигадані API**: функції, props чи пакети, яких не існує (перевірте в документації).
- [ ] **Ігнорування вашої системи**: нові кольори замість токенів, нові класи замість наявних.
- [ ] **Доступність**: `label` до полів, `aria-*`, фокус, кнопка замість `div` з `onClick`.
- [ ] **Обробка станів**: чи є loading / error / empty.
- [ ] **Зайве**: нові бібліотеки, надлишковий код, «покращення», про які не просили.
- [ ] **Запуск**: `npm run lint` і `npm run build` без помилок, сторінка працює в браузері.
