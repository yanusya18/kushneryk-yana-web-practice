# Порівняння: чистий CSS і Tailwind CSS (ПР 5)

Одна й та сама сторінка **«Контакти»** зверстана двома способами:
- чистий CSS: `client/static/contacts.html` + `client/assets/css/*.css`
- Tailwind: `client/static/contacts.tailwind.html` + `client/assets/css/tailwind.css`

Обидві версії використовують **ті самі токени** (`tokens.css`) і візуально збігаються
(різниця в межах допуску ±4 px). Числа нижче виміряно на реальних файлах проєкту.

## Виміряні показники

| Показник | Чистий CSS | Tailwind |
|---|---|---|
| Файли стилів, що підключає сторінка | `tokens` + `reset` + `base` + `components` (4 файли) | `tokens` + `tailwind` (2 файли) |
| Розмір CSS, байт (gzip) | 18 773 (5 665) | 15 567 (4 538) = tailwind 10 455 + tokens 5 112 |
| Вихідний код стилів | 480 рядків, написаних вручну | `input.css` 11 рядків + `tailwind.config.js` ≈ 30 рядків; решта генерується |
| Розмір HTML, байт (gzip) | 5 313 (1 857) | 8 367 (2 537) |
| Атрибутів `class` у HTML | 10 | 45 (довгі ланцюжки утиліт) |
| Разом HTML + CSS, байт (gzip) | 24 086 (7 522) | 23 934 (7 075) |
| Крок збірки | не потрібен | потрібен: `npm run build` |

**Як це читати.** Чистий CSS тут покриває **весь сайт** (шапка, картки, hero, таблиця, форми), а
Tailwind-файл містить лише утиліти, які реально зустрілися в **одній** сторінці. Тому пряме
порівняння розмірів на користь Tailwind перебільшене: якщо Tailwind зібрати для всіх 5 сторінок, його CSS зросте.
Зате HTML у Tailwind помітно важчий і гірше читається.

## Переваги й недоліки

| | Чистий CSS | Tailwind (utility-first) |
|---|---|---|
| ➕ | Чистий семантичний HTML; повний контроль; не потрібна збірка; стилі повторно використовуються через класи компонентів | Швидке прототипування без перемикання між файлами; єдина система відступів/кольорів; немає «мертвого» CSS після збірки; не вигадуєш імен класів |
| ➖ | Треба вигадувати імена класів; CSS поступово розростається; ризик конфліктів специфічності | Довгі ланцюжки класів у HTML; крива навчання; потрібна збірка; дублювання розмітки без компонентів (у React це вирішується компонентом) |
| Підходить | Невеликі сайти, навчання основ, серйозна кастомізація | Команди й проєкти з компонентним підходом (React) |

## Висновок для проєкту
Основні сторінки залишено на чистому CSS (він наочно показує Flexbox, Grid і медіа-запити).
Tailwind використано на сторінці контактів для порівняння; у ПР 7 (React) його зручно поєднати з компонентами.
