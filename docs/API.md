# REST API сайту коворкінгу (ПР 8)

Базова адреса (локально): `http://localhost:3001` · формат обміну: **JSON** (`Content-Type: application/json`).
Код: `server/` (Express 5, дані — JSON-файл `server/data/db.json`). Опублікований API: див. `README.md`.

## Токен адміністратора (ПР 10)

На опублікованому сайті будь-хто міг би додавати й видаляти місця, тому **POST, PUT і DELETE `/api/items`** захищено:

- якщо на сервері задано змінну середовища `ADMIN_TOKEN`, запит мусить містити заголовок `X-Admin-Token: <токен>`, інакше відповідь — **401** `{ "message": "Потрібен токен адміністратора ..." }`;
- якщо `ADMIN_TOKEN` не задано (локальна розробка) — перевірка вимкнена, усе працює як раніше;
- читання (`GET`) і бронювання/контакти токена не потребують — ними користуються звичайні відвідувачі;
- у React-застосунку токен вводиться на сторінці `/manage` і зберігається лише в `sessionStorage` вкладки;
- у Postman токен задається змінною колекції `adminToken`.

Це простий захист для навчального проєкту, а не повноцінна авторизація (немає акаунтів, ролей і сесій).

## Таблиця ендпоінтів

| Метод | URL | Тіло запиту | Успішна відповідь | Помилки |
|---|---|---|---|---|
| GET | `/api/health` | — | **200** `{ "status": "ok" }` | — |
| GET | `/api/items` | — (query: `q`, `type`, `maxPrice`, `includeInactive`) | **200** масив місць | 400 |
| GET | `/api/items/:id` | — | **200** місце | 400, 404 |
| GET | `/api/items/:id/availability?date=РРРР-ММ-ДД` | — | **200** масив зайнятих проміжків | 400, 404 |
| POST | `/api/items` | місце (див. нижче) | **201** створене місце + заголовок `Location` | 400, 401, 409 |
| PUT | `/api/items/:id` | місце (повна заміна) | **200** оновлене місце | 400, 401, 404, 409 |
| DELETE | `/api/items/:id` | — | **204** без тіла | 400, 401, 404, 409 |
| POST | `/api/bookings` | бронювання (див. нижче) | **201** підтвердження | 400, 409 |
| POST | `/api/contact` | форма контактів | **201** `{ id, message }` | 400 |
| будь-який інший | — | — | — | **404** |

Загальні помилки для всіх маршрутів: **400** — зламаний JSON, **413** — тіло більше 100 КБ, **500** — внутрішня помилка.

## Формат помилок

Усі помилки — JSON із полем `message`. Помилки валідації мають ще й перелік по полях:

```json
{
  "message": "Некоректні дані бронювання.",
  "errors": [
    { "field": "customerEmail", "message": "Вкажіть коректний email." },
    { "field": "consent", "message": "Потрібна згода на обробку персональних даних." }
  ]
}
```
Конфлікт бронювання (409) додатково повертає, з чим перетнулося:
```json
{ "message": "Час уже заброньовано: 10:00–13:00.", "conflict": { "startTime": "10:00", "endTime": "13:00" } }
```

## Коди відповідей, що використовуються

| Код | Коли |
|---|---|
| 200 OK | Успішні GET і PUT |
| 201 Created | Створено місце, бронювання, повідомлення |
| 204 No Content | Місце видалено (тіла немає) |
| 400 Bad Request | Некоректні дані, параметри, id або JSON |
| 404 Not Found | Місця немає; невідомий маршрут |
| 409 Conflict | Назва місця вже існує; час уже заброньовано; видалення місця з майбутніми бронюваннями |
| 413 Payload Too Large | Тіло запиту завелике |
| 500 Internal Server Error | Непередбачена помилка сервера (деталі лише в лозі сервера) |

## Модель даних

**Workspace — робоче місце**

| Поле | Тип | Правила (POST/PUT) |
|---|---|---|
| `id` | number | призначає сервер, не змінюється |
| `name` | string | обов'язкове, 2–80 символів, унікальне (без урахування регістру) |
| `type` | string | `open-space` · `fixed-desk` · `private-office` · `meeting-room` |
| `description` | string | обов'язкове, 10–1000 символів |
| `pricePerHour` | integer | 1–10000 (саме число, не рядок) |
| `capacity` | integer | 1–100 |
| `amenities` | string[] | необов'язкове; значення: `wifi`, `socket`, `chair`, `lamp`, `monitor`, `screen`, `whiteboard`; дублікати прибираються |
| `image` | string | необов'язкове; одне з наявних зображень проєкту; за замовчуванням — за типом місця |
| `imageAlt` | string | необов'язкове, до 200 символів; за замовчуванням формується з назви й типу |
| `isActive` | boolean | необов'язкове, за замовчуванням `true`; неактивні місця не показуються публічно |

**Booking — бронювання** (`POST /api/bookings`)

| Поле | Тип | Правила |
|---|---|---|
| `workspaceId` | integer | місце має існувати й бути активним |
| `date` | `РРРР-ММ-ДД` | реальна дата, не в минулому |
| `startTime`, `endTime` | `ГГ:ХХ` | повні години; відкриття 08:00, закриття 22:00; кінець пізніше за початок; якщо дата — сьогодні, початок має бути в майбутньому |
| `customerName` | string | 2–60 символів |
| `customerEmail` | string | коректний email |
| `customerPhone` | string | `+380XXXXXXXXX` |
| `consent` | boolean | має бути `true` |

Вартість (`totalPrice`) **рахує сервер**: ціна за годину × кількість годин; значення від клієнта ігнорується.
Відповідь `201`: `{ id, workspaceId, date, startTime, endTime, customerName, totalPrice, status }` (email і телефон не повертаються).

**Правило конфлікту:** два бронювання одного місця на одну дату конфліктують, якщо `start1 < end2` і `start2 < end1`.
Отже 10:00–13:00 і 13:00–15:00 **не** конфліктують. Перевірка й запис виконуються послідовно (черга в `store.update`),
тому два одночасні запити на один слот не можуть обидва пройти.

**Contact** (`POST /api/contact`): `name` (2–60), `email`, `phone` (необов'язковий, `+380…`), `topic` (`tour` · `booking` · `team` · `other`),
`message` (10–1000), `consent` (`true`).

## Приклади (curl)

```bash
# Список місць
curl http://localhost:3001/api/items

# Створити місце
curl -X POST http://localhost:3001/api/items -H "Content-Type: application/json" \
  -d '{"name":"Місце D1","type":"open-space","description":"Тихе місце біля вікна","pricePerHour":70,"capacity":1}'

# Зайняті години місця 1 на дату
curl "http://localhost:3001/api/items/1/availability?date=2026-12-01"

# Забронювати
curl -X POST http://localhost:3001/api/bookings -H "Content-Type: application/json" \
  -d '{"workspaceId":2,"date":"2026-12-01","startTime":"10:00","endTime":"12:00","customerName":"Яна","customerEmail":"yana@example.com","customerPhone":"+380501234567","consent":true}'

# Видалити
curl -X DELETE http://localhost:3001/api/items/7 -i
```

## Налаштування (`server/.env`, шаблон — `server/.env.example`)

| Змінна | За замовчуванням | Призначення |
|---|---|---|
| `PORT` | 3001 | Порт сервера |
| `CORS_ORIGIN` | `http://localhost:5173` | Дозволені адреси клієнта (через кому) |
| `DATA_FILE` | `data/db.json` | Файл даних (створюється автоматично) |
| `TIMEZONE` | `Europe/Kyiv` | Часовий пояс для «сьогодні» й «зараз» |
| `NODE_ENV` | — | `production` приховує деталі 500-помилок |

## Особливості реалізації

- **Middleware** (порядок у `server/src/app.js`): логування запитів → CORS → розбір JSON → маршрути → 404 → централізований обробник помилок (500).
- **CORS:** сервер дозволяє запити лише з адрес у `CORS_ORIGIN`; для інших браузер заблокує відповідь.
- **Приватність:** `availability` віддає лише проміжки часу без імен і контактів; лог не містить тіл запитів.
- **Видалення місця** заборонене (409), якщо на нього є майбутні підтверджені бронювання.
- **Скидання даних:** `npm run reset-db` у папці `server`.

## Відомі обмеження навчального проєкту

Немає авторизації (будь-хто може викликати POST/PUT/DELETE `/api/items`), немає обмеження частоти запитів,
дані зберігаються у файлі, а не в СУБД. Для реального сайту це треба додати.
