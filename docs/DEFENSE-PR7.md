# Підготовка до захисту ПР 7

## Контрольні питання

**1. Чим props відрізняються від state?**
**Props** — вхідні дані, які компонент отримує від батька; компонент їх не змінює (лише читає).
Приклад: `<Card workspace={…} />` — `Card` отримує `workspace` і лише відображає його.
**State** — власні дані компонента, що змінюються з часом; зміна стану (через `setState`) перемальовує компонент.
Приклад: `menuOpen` у `Header`, `values` форми в `BookingForm`. Дані течуть вниз (props), події — вгору (`onChange`, `onBooked`).

**2. Коли виконується `useEffect` і навіщо масив залежностей?**
Ефект виконується **після** рендера (і після монтування). Масив залежностей визначає, коли його запускати знову:
`[]` — один раз; `[a, b]` — коли змінилось `a` або `b`; без масиву — після кожного рендера.
У `useFetch` залежності `[fetcher, attempt]`: запит повторюється, коли змінився id/дата (інший `fetcher`)
або натиснули «Спробувати ще раз» (`attempt`). Функція, яку повертає ефект, — очищення (`ignore = true`), вона
виконується перед наступним запуском і при розмонтуванні.

**3. Навіщо потрібен `key` при рендерингу списків?**
`key` дозволяє React розпізнати, який саме елемент списку змінився, додався чи зник, і оновити лише потрібне, не
перестворюючи решту й не плутаючи їхній стан. Ключ має бути стабільним і унікальним серед сусідів (у нас `workspace.id`,
`code`), а не індексом масиву. Окремий прийом: `<BookingForm key={workspace.id} …>` — при зміні id React створює форму наново,
тому поля не «переносяться» на інше місце.

**4. Які помилки AI-асистента ви помітили і як їх виявили?**
Це питання про **вашу** роботу з асистентом: відповідайте за таблицею в `docs/AI.md` (що виправили й чому).
Підказка, як виявляти: `npm run lint`, `npm run build`, перегляд консолі браузера, перевірка за чек-листом у `docs/AI.md`.

## Пояснення ключових фрагментів
- **`main.jsx`** — підключає CSS ПР 5, додає клас `js` на `<html>`, обгортає `<App/>` у `<BrowserRouter>` (маршрутизація за адресою без перезавантаження).
- **`App.jsx`** — `<Routes>`: `index` — головна, `items/:id` — параметр адреси, `path="*"` — 404. Усі вкладені в `Layout`.
- **`Layout.jsx`** — `<Outlet/>` показує сторінку поточного маршруту; ефект скролить угору або до `#pricing`.
- **`useFetch`** — стан `{data, loading, error}`; `loading` виводиться з порівняння «ключа» запиту, `ignore` захищає від гонитви запитів.
- **`useFormValidation` + `FormField`** — контрольовані поля; помилки показуються після `blur` (`touched`); кнопка вимкнена, поки `isValid === false`;
  `aria-invalid` і `aria-describedby` — доступність.
- **`BookingForm`** — дата → `useFetch(getBookingsFor)` → `buildBookingRules({ busy })` → перевірка перетину `start1 < end2 && start2 < end1`
  (`utils/booking.js`) → `createBooking` повторно перевіряє доступність → `onBooked` відкриває `Modal`.
- **`Modal`** — нативний `<dialog>`: `showModal()` у ефекті; Esc закриває сам браузер; клік по підкладці — `event.target === dialog`.
- **`CardList`** — делегування подій: один `onClick` на контейнері, `closest('.card')`, перехід через `useNavigate`.
- **`useTheme`** — `useSyncExternalStore` стежить за системною темою; вибір зберігається в `localStorage` і ставиться як `data-theme`.
- **`api.js`** — єдина точка доступу до даних; у ПР 8 тут з'явиться `fetch` до Express без змін у компонентах.

## Що показати викладачу
1. `npm install` → `npm run dev` у `client/`; відкрити сайт, пройтись по `/`, `/catalog`, `/items/1`, `/contacts`, неіснуючій адресі (404).
2. Дерево компонентів (`docs/COMPONENT-TREE.md`) і де props / де state.
3. Бронювання: дата завтра → зайняті години → спроба 10–12 (конфлікт) → 13–15 (успіх, модальне вікно).
4. Демо-режими станів: `/catalog?demo=loading`, `?demo=error`, `?demo=empty`.
5. Кнопка теми й меню на ширині 360 px (DevTools → Device Mode).
6. `docs/AI.md` із **вашою** таблицею та 3 виконаними задачами.
7. Уміти внести невелику зміну наживо: напр., змінити кількість «Популярних місць» у `HomePage` (`slice(0, 3)`) або мінімальну довжину повідомлення в `ContactForm`.
