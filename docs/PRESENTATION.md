Вимога: **7–10 слайдів, 5–7 хвилин** за схемою *проблема → рішення → дизайн → технології → демо → метрики → що далі*. Нижче — структура з текстом для слайдів і тим, що казати. Значення в `[дужках]` підставте свої.

## Структура слайдів (9 слайдів)

### 1. Титульний
- «Простір» — сайт коворкінгу з онлайн-бронюванням робочих місць
- Кушнерик Яна · навчальна практика «WEB-технології та WEB-дизайн» · варіант 1
- QR-код на опублікований сайт

### 2. Проблема
- Люди шукають, де працювати: незрозуміло, які місця вільні й скільки вони коштують
- Бронювання по телефону/месенджеру: довго, є ризик накладок на той самий час
- Мета: показати місця, ціни й **забронювати на конкретну дату й час за кілька кроків**

### 3. Рішення
- Каталог місць з фільтрами, пошуком і сортуванням
- Сторінка місця: фото, обладнання, зайняті години на обрану дату
- Бронювання з миттєвою перевіркою доступності та підрахунком вартості
- Контактна форма; сторінка керування місцями; встановлюється як застосунок (PWA)

### 4. Дизайн
- Етапи: персони (2) → user flow → wireframe 4+ екранів → дизайн-система → макети desktop і mobile (Figma: [посилання])
- Дизайн-система: токени (кольори, відступи, радіуси), світла й темна тема, компоненти зі станами
- Мобільний-first: 360 / 768 / 1280 px
- *Покажіть 1–2 скриншоти макета поруч із реалізацією*

### 5. Технології й архітектура
- Схема: `React (Vite) на Vercel ⇄ REST API (Express) на Render ⇄ JSON-файл`
- Клієнт: React 19, React Router, власні хуки (`useFetch`), CSS-токени; сервер: Express 5, валідація, middleware (логування, 404, 500)
- Якість: Vitest + React Testing Library, GitHub Actions (CI), автодеплой із `main`
- AI-інструменти: [які й для чого використані; що довелось виправляти]

### 6. Ключова функція — бронювання
- Правило перетину: `start1 < end2 && start2 < end1` (10–13 і 13–15 не конфліктують)
- Перевірка двічі: у браузері (миттєвий зворотний зв'язок) і на сервері (справжній захист, відповідь 409)
- Запис серверу виконується по черзі — два одночасні запити на той самий час не пройдуть обидва
- *Покажіть екран із повідомленням «Місце зайняте з 10:00 до 13:00»*

## Сценарій демонстрації (5–7 хв)

**За 3 хвилини до початку:** відкрийте `…/api/health` (щоб безкоштовний сервер «прокинувся»), відкрийте сайт у новій вкладці, переконайтесь, що інтернет працює. Запасний варіант на випадок збою — заздалегідь записаний екран (1–2 хв) і скриншоти.

| Час | Дія | Що сказати |
|---|---|---|
| 0:00–0:45 | Слайди 1–3 | проблема й ідея, коротко |
| 0:45–1:30 | Слайд 4 + відкрити Figma | дизайн-процес, токени, темна тема |
| 1:30–2:15 | Слайд 5 | схема клієнт ⇄ API, інструменти |
| 2:15–4:45 | **Живий сайт** | головна → каталог (пошук «вікна», фільтр за типом, сортування) → картка місця → вибрати завтра 11:00–12:00 (помилка зайнятості) → 13:00–15:00 → заповнити форму з помилкою email → виправити → «Забронювати» → вікно підтвердження → повторити той самий час (місце вже зайняте) |
| 4:45–5:15 | Телефон або DevTools | тема, меню на 360 px, установка PWA, офлайн-сторінка (Network → Offline) |
| 5:15–6:00 | Слайд 8 | Lighthouse, axe, тести |
| 6:00–6:45 | Слайд 9 | що далі, висновки |

**Підготуйтесь до зміни коду наживо** (3–5 хв після демо за регламентом): знайдіть файли `booking.js` (правило перетину), `validators.js` (email/телефон), `api.js` (запити), `sw.js` (кеш). Вміти пояснити, чому саме такі рішення.
